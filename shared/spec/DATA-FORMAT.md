# Taskly Data Format (Contract)

> Version 5 (`PRAGMA user_version = 5`). Canonical for **all** platforms.
> Any schema change must land in this file and in all platform apps in the
> same release. Never break an existing `.db` file.

## 1. File locations (all desktop platforms)

| Item | Path |
|---|---|
| App directory | `~/.taskly/` (created on demand) |
| Default database | `~/.taskly/tasks.db` |
| Config | `~/.taskly/config.ini` |
| Home resolution | Windows: `USERPROFILE` → `HOME`; macOS/Linux: `HOME` |

Resolution order for the active DB: `--db` argument → config `last-db-path`
→ `~/.taskly/tasks.db`. Keeping everything under one folder is deliberate:
users sync `.taskly/` (or any folder holding their `.db`) via iCloud /
OneDrive / Dropbox.

## 2. Pragmas

- `PRAGMA journal_mode = WAL;` on every connect (persistent once set; much
  safer when the file lives in a cloud-synced folder).
- `PRAGMA user_version` is written **outside** any transaction (a no-op
  inside one).

## 3. Schema (fresh install creates v5 directly)

```sql
CREATE TABLE lists (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    icon TEXT,
    color INTEGER,
    created_at TEXT NOT NULL
);
CREATE TABLE tasks (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    list_id INTEGER,
    text TEXT NOT NULL,
    due_date TEXT,
    due_time TEXT,
    completed INTEGER DEFAULT 0,
    created_at TEXT NOT NULL,
    notes TEXT,
    priority INTEGER DEFAULT 0,
    tags TEXT,
    subtasks TEXT,
    url TEXT,
    FOREIGN KEY (list_id) REFERENCES lists (id)
);
CREATE INDEX IF NOT EXISTS idx_tasks_list_id ON tasks(list_id);
CREATE INDEX IF NOT EXISTS idx_tasks_completed ON tasks(completed);
CREATE INDEX IF NOT EXISTS idx_tasks_due_date ON tasks(due_date);
INSERT INTO lists (name, icon, color, created_at)
VALUES ('工作', '📋', -16745729, '<created_at>');
```

- Default list name is the literal `工作` (not localized).
- `TodoList.defaultIcon = "📋"`; `TodoList.defaultColor = ARGB 0xFF007AFF`
  (system blue, since the 0.7.0 Reminders redesign; pre-0.7.0 DBs may hold
  the old terracotta `0xFFC15F3C` = `-4104388` — both are valid stored
  values). Stored as signed 32-bit; list colors are **signed ARGB ints**;
  every platform must bit-cast through Int32/uint, never through a sign-
  preserving wider integer.

## 4. Storage formats

| Column | Format |
|---|---|
| `due_date` | TEXT `yyyy-MM-dd` (local time) |
| `due_time` | TEXT `HH:mm` (24h) |
| `created_at` | TEXT ISO-8601 round-trip with local offset (e.g. `2026-09-15T14:23:45.1234567+08:00`; fractional digits may vary by platform) |
| `completed` | INTEGER 0/1 |
| `color` | INTEGER signed ARGB |
| `priority` | INTEGER 0 none · 1 low · 2 medium · 3 high (NULL reads as 0) |
| `tags` | TEXT JSON array of strings (e.g. `["work","week"]`); NULL or unparseable reads as empty |
| `subtasks` | TEXT JSON array of `{"text": string, "done": bool}` objects in stored order; NULL or unparseable reads as empty |
| `url` | TEXT ≤2048 chars; blank/NULL = absent |

"Today" is decided **locally**: `date(t.due_date) = '<yyyy-MM-dd of now>'`.

## 5. Migrations

Run in an explicit transaction (DDL + INSERT atomic); set `user_version`
after commit. Detection is idempotent (`PRAGMA table_info` before
`ALTER TABLE ADD COLUMN`).

| oldVersion < | Action |
|---|---|
| 2 | create the three indexes above |
| 3 | `lists.icon TEXT`, `lists.color INTEGER` |
| 4 | `tasks.due_time TEXT`, `tasks.notes TEXT` |
| 5 | `tasks.priority INTEGER DEFAULT 0`, `tasks.tags TEXT`, `tasks.subtasks TEXT`, `tasks.url TEXT` |

Fresh DBs (`oldVersion == 0`) create v5 directly and seed the default list.
After connect, re-ensure `lists.icon`/`lists.color` exist (belt-and-braces,
failures logged only).

## 6. Row ↔ model mapping

`tasks` + `LEFT JOIN lists l ON t.list_id = l.id` (`l.name AS list_name`):

`id`, `list_id`, `text`, `due_date`, `due_time`, `completed` (true iff ==1),
`created_at`, `notes`, `list_name` (derived, never persisted), `priority`
(NULL → 0), `tags` (JSON, §4), `subtasks` (JSON, §4), `url`.

## 7. Config (`config.ini`)

INI, no sections; `key = value`; `;`/`#` comments; first `=` splits; both
sides trimmed; keys case-insensitive. Writer emits two fixed header lines:

```
# Taskly configuration
# This file is automatically generated and managed by Taskly.
```

| Key | Meaning | Default |
|---|---|---|
| `last-db-path` | last opened DB — written by `open_database`/`create_database`/`migrate_database` on success, read at startup (read also accepts legacy `last_db_path`, which rewrites must carry through). **Empty/absent = no database chosen → hosts show the startup gate (PRODUCT-SPEC §2a); it is never silently defaulted** for the gate flow. The CLI keeps its own `--db` → default fallback | — |
| `last-db-name` | display name of the current database — written by `create_database` (entered name), `open_database` (file stem when unregistered); sidebar identity and Settings 数据 group read it | — |
| `language` | `zh` / `en` | `zh` |
| `theme` | `system` / `light` / `dark`; Windows applies it before the first window paint | `system` |
| `last-selected-list-id` | int as string; unparseable → 0 | `0` |
| `default-list-id` | int as string; quick-add target when no list is selected (PRODUCT-SPEC §2a 新任务 group); unparseable or dangling → fall back to the first list | `0` |
| `global-quick-add` | recorded accelerator string (e.g. `⌃⌥Space`); display-only — **not registered with the OS** in this slice | — |
| `last-update-check` | unix seconds of the last auto-update check (UPDATE.md throttle) | `0` |
| `auto-check-updates` | `1`/`0` — whether the silent update checks run (UPDATE.md) | `1` |

Filename conventions (PRODUCT-SPEC §2a): `create_database` and
`migrate_database` build their target as `<folder>/taskly.sqlite` —
exclusive, atomic, rejecting any existing target; open/relocate accept
`*.db *.sqlite *.sqlite3` and must not create missing files (the CLI's
`--db` open-or-create semantics are unchanged).

## 8. Conformance

Each platform's test suite must: create a fresh DB and assert the schema
above; open a fixture DB written by another platform and round-trip every
column; migrate a `user_version=0..4` fixture to 5 idempotently.

## 9. Backup JSON (`taskly-backup` v1)

Human-readable, UTF-8, 2-space pretty-printed. `export_backup` writes it;
`preview_backup` validates and counts it; `restore_backup` replaces the
current database's lists and tasks with it in **one transaction** (task
IDs are reassigned by the database, list references are re-mapped through
the restored lists; `created_at` values are preserved verbatim).

```json
{
  "format": "taskly-backup",
  "version": 1,
  "exportedAt": "2026-11-15T20:51:31+08:00",
  "lists": [
    { "id": 1, "name": "工作", "icon": "📋", "color": -16745729 }
  ],
  "tasks": [
    {
      "listId": 1,
      "text": "整理读书笔记",
      "completed": false,
      "dueDate": "2026-11-15",
      "dueTime": "14:00",
      "notes": "第三章",
      "createdAt": "2026-11-15T09:00:00+08:00",
      "priority": 2,
      "tags": ["读书"],
      "subtasks": [{ "text": "摘录要点", "done": true }],
      "url": ""
    }
  ]
}
```

Validation (`preview_backup` / `restore_backup`, PRODUCT-SPEC §2a):
`format` == `taskly-backup`, `version` == 1, `lists` and `tasks` arrays
present, ≤10 000 tasks and ≤5 MB file size, every task carries the fields
above (`url` may be `""` = absent; optional scalars nullable; list ids,
names and icon/color shapes valid; every task `listId` must reference a
list in the same file). Any violation rejects the whole file — no partial
restore, current data untouched. Restore drops the current database's
lists and tasks first; the default list is **not** re-seeded (the backup's
lists are authoritative).
